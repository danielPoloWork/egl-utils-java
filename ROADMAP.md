# ROADMAP — egl-utils-java

The negotiated milestone roadmap. Authored by the **producer** in the `plan` phase
(`.eados-core/orchestrator/commands/plan.md`) from the approved RFCs recorded in
`orchestrator/project.yaml` → `delivery_state.refs.rfcs`. The `roadmap-covers-rfcs` gate
(`traceability.py`) reads the `## Milestone N` sections below; `plan → scaffold` is illegal until
every recorded RFC is addressed by at least one milestone.

**Every item carries a size and a route.** Size is a macroscopic T-shirt estimate
(`plan.yaml sizing_scale: XS S M L XL`) — not story points. Route is the advisory model/effort
recommendation from the `os/routing` policy (ADR-0017), stated as **tier / effort**, never a model
name — names rot, the dated `catalog:` owns them. Routes below were resolved with
`route_advice.py`, not asserted; the signals that earned each one are listed under
[Routing basis](#routing-basis). **The route is advisory: the human keeps final model authority.**

**Latest checkpoint:** [2026-08-05 — `AuditLog`, and a trap reproduced rather than described (item 3.3)](docs/journal/2026/08/2026-08-05-audit-log-redaction.md).
The journal index is [`docs/journal/`](docs/journal/README.md). This pointer is step 3 of the
checkpoint protocol and had no target in this file until item 2.1 created the first checkpoint.
Items 3.1 and 3.2 wrote their checkpoint files and skipped steps 2 and 3; item 3.3 back-filled both
index rows and this pointer, because an index with holes is worth less than no index.

## The design debt this roadmap makes visible

The negotiation protocol is explicit: *"Each item references an approved RFC — no roadmap item
without a design behind it."* Measured against that rule, **one milestone of eight is covered**:

| Milestone | RFC behind it | Status |
|---|---|---|
| M1 repository foundations | ADR-001 + ADR-004 (both Accepted) — no RFC | structural decisions already settled by ADR; see note below |
| **M2 core foundations** | **RFC-0001** | **covered** |
| M3 core cross-cutting | — | **needs an RFC** (item 3.0) |
| M4 json and jdbc | — | **needs an RFC** (item 4.0) |
| M5 concurrent | — | **needs an RFC** (item 5.0) |
| M6 security | ADR-003 covers the JWT library choice only | **needs an RFC** (item 6.0) |
| M7 adapters and test support | — | **needs an RFC** (item 7.0) |
| M8 release engineering | — | see 8.0 note |

So this roadmap schedules **five more RFCs** as first-class items (3.0, 4.0, 5.0, 6.0, 7.0). That is
not padding: `workflow.yaml` defines `plan → design` as a legal, non-human-gated transition precisely
so a new RFC can re-open planning without restarting the project. Each of those items is a return to
the `design` phase, and the milestone's implementation items are blocked on it.

**M1 is the deliberate exception.** Its content is structural and already decided by two Accepted
ADRs (ADR-001 module split, ADR-004 generated layout). Writing an RFC to re-decide an accepted ADR
adds ceremony, not a decision. M1 items therefore cite the ADR that governs them.

**M8 carries no RFC item.** Its work is CI and release plumbing implementing NFR-09 through NFR-12,
which the specification already states normatively. Item 8.3 is the exception — it changes a stated
NFR's enforcement model — and is flagged `decision-heavy` accordingly.

## Sequencing

No dates — the project is milestone-driven pre-1.0 (`governance.version_start`). This is the
dependency order, which is what actually constrains the work:

```
M1 ─────────────────────────────────────────► everything (ADR-004: no code before the reactor)
 └─ 1.1 blocks 1.2–1.9 and all of M2

M2 ──► M3, M4, M5              [Result/ErrorDetail is the shared error vocabulary]
 │
 ├─ M3 ──┐
 ├─ M4 ──┤
 └─ M5 ──┴──► M7               [adapters bind what the modules expose]
              M6 ─┘            [independent of M3/M4; needs only M2]

M6 + M7 ──► M8                 [japicmp needs a published surface; 8.6 audits the finished one]
```

M3, M4, M5 and M6 are mutually independent once M2 lands — with capacity of one they are sequential
in practice, and the order among them is the owner's priority call, not a technical constraint.
**8.3 is the exception to that ordering:** it can be pulled forward at any time after 1.8, and doing
so would stop the M2 perf numbers from sitting in an advisory limbo for the whole project.

## Routing basis

Routes were resolved with `route_advice.py` against the `os/routing` policy, not asserted. The
signal sets and their verdicts:

| Signals | Verdict | Applied to |
|---|---|---|
| `severity:high` + flag `decision-heavy` | **frontier-reasoning / max** | 1.1, 8.3 — a wrong foundational call is the most expensive artifact here |
| `severity:high` + flag `sets-pattern` | **frontier-reasoning / high** | 1.6, 1.7, 2.1, 2.2, 8.1 — first of its class; every follower copies the template |
| `security` + `severity:high` | **frontier-reasoning / high** | 3.3, 4.1, 4.3, 6.1–6.4, 8.4, 8.5, 8.6 — on security posture a subtle miss dwarfs the routing saving |
| `adr` | **frontier-reasoning / high** | 1.10, 3.0, 4.0, 5.0, 6.0, 7.0, 5.3 — an RFC-, ADR- or interface-defining item is decision-heavy by definition |
| `severity:high` | **standard / high** | 1.4, 1.5, 2.3, 2.4, 4.4, 4.5, 5.1, 5.2, 7.1, 7.3, 7.4 |
| `severity:medium` | **standard / medium** | 1.2, 1.3, 1.8, 1.9, 2.5, 3.1, 3.2, 4.2, 7.2, 8.2 |

Two judgment calls, stated because the tool cannot make them: **4.5 `PageRequest` was not labelled
`security`** even though its sort whitelist is an injection defence — its primary job is pagination,
and labelling every item containing one validation as `security` would route the whole roadmap to the
top tier and make the signal meaningless. Conversely **4.1 `JsonMapper` was**, despite being a
three-flag configuration change: getting default typing wrong is a known CVE class, so the
consequence — not the size — earns the route.

At run time, `route_advice.py --check --current-model <id>` compares a step's route against the
session model and prints `ROUTE-OK` / `ROUTE-MISMATCH`. It never switches the model; model authority
is the human's (ADR-0017).

- [x] 3.0 **RFC-0002 — cross-cutting core contracts.** **Done and approved:** [RFC-0002](docs/rfc/0002-cross-cutting-contracts.md) was drafted `Proposed` with an empty `approved-by:` — no RFC self-approves (AGENTS.md §6) — and **the owner approved it in session on 2026-08-02**, flipped in a separate commit so the two acts are visible as two acts. Its silent half is recorded rather than hidden: a sink that starts failing after the one warning was spent fails quietly, and a host that needs to know needs a health check, not a log line. **The fallback logs at `DEBUG`, and that is a decision with a stated cost** — one record per invocation at `INFO` would be on by default in exactly the hosts that configured nothing, which is how instrumentation becomes the dominant cost of the method it measures; the price is that timings are invisible until a host enables the level, and the Javadoc says so rather than leaving it to be discovered. **A locale trap sits in the fallback and is closed by test:** `System.Logger` substitutes with `MessageFormat`, which renders a `Long` through the *default* locale, so a raw duration prints `1.234.567` on an Italian JVM and `1,234,567` on a US one — the same measurement in two log lines no expression can parse — so every parameter reaches the logger pre-rendered, and `rendersTheDurationIdenticallyOnEveryLocale` sets both locales and asserts one string, the shape C-03 uses for identifiers. Timing is on `System.nanoTime()`: a wall clock can step backwards under NTP and a negative latency is not a value any backend can interpret. Failures are timed too, in a `finally`, with an `Error` counted as a completion rather than dropped. A blank `name` is rejected at the call site, because an unattributable metric is far cheaper to refuse here than to find in a dashboard later. **The compliance register is untouched on purpose:** nothing on this path carries an argument value — `name` comes from a method signature — so C-01 gains no call site and inventing a row for a property the API cannot violate would dilute the register. **No benchmark, because no NFR names FR-15**; the only performance statements made are structural and negative (nothing on the measured path synchronises; the fallback tests the level before rendering). **One build-config change was forced and is worth flagging, because `clean verify` does not catch it:** `throws Throwable` trips Checkstyle's `IllegalThrows`, and `checkstyle:check` is a *separate* CI goal — so the ruleset gains `SuppressWarningsFilter` + `SuppressWarningsHolder`, which is what makes the `@SuppressWarnings("CheckName")` mechanism AGENTS.md §9 already prescribes actually work; two methods carry it with the reason inline. A path-keyed suppressions file was the alternative and silences a rule for whole files including code written later. **Item 7.x would have hit the same wall**: an AspectJ `@Around` advice must declare `throws Throwable`. Verified on Temurin **17.0.20+8** and **21.0.12+8**: `clean verify` (`Tests run: 239`, up from 216), `-Pjmh,jcstress verify` (**112 results, 0 failed, 0 interesting** — the new harness observing only `1, both ran`), `spotless:check -pl '!d4np-bom'`, `checkstyle:check`, `validate`, and `consistency_lint.py`. - [x] 3.3 `AuditLog` with a field-level redaction allowlist and `@Sensitive` opt-out (RFC-0002; FR-16) — **done, and it closes Milestone 3 ([ADR-0022](docs/adr/0022-redact-at-capture-behind-a-typed-event.md)).** RFC-0002 arrived with more contract than any other item in this project — four layers, their precedence, whole-token matching, simple values only, depth 3, `record` throws, public accessors only — so the work was the **shape**, and five of those decisions turned out to be load-bearing. **The event is a final class rather than a record, and that is the one structural decision the redaction rule depends on:** a public record's canonical constructor is public, so `AuditEvent` as a record would be a documented way to hand `AuditLog.record` an "audit event" full of plaintext — the guarantee would hold for our capture path rather than for the type. The constructor is package-private and `capture` is the only way to obtain one; the nested `Change` **is** a record, and the split paid for itself as documentation: a record's deserialisation runs its canonical constructor, so `Change` validates for free, while the class needs a `readResolve` to re-run the constructor a stream would otherwise skip (without it, a crafted stream decides whether `changes` is modifiable). **The trap RFC-0002 was written around is reproduced rather than asserted:** with the composite guard removed, the event carries `Credentials[user=alice, password=hunter2]` and `neverRendersACompositeAsText` turns red — the `@Sensitive` marker present, correct, and completely bypassed by one `String.valueOf`. Removing layer 1 instead turns four tests red, including the API-key one. **Markers are read from every declaration site and the type is read from the value**, and the first half is a safety property rather than convenience: a `@Sensitive` written on the field of a JavaBean while the engine looked only at the getter would be present and bypassed, which is the worst available outcome because it looks right in review. The second half closes the `Object`-declared hole — a component whose declared type is `Object` and whose runtime value is a record still gets all four layers. **`@Audited` is deliberately not `@Inherited`:** an inherited permit-everything marker means a subclass that adds a component leaks it by default, which is the exact failure the RFC rejected the denylist for, moved across a class boundary where it is less visible. The consequence is stated rather than discovered — **a proxied entity is not auditable**, because a CGLIB or Hibernate proxy is a generated subclass, and it fails loudly instead of producing an empty record. **RFC-0002's own illustration collides with RFC-0002's own list, and the list wins:** the recursion rule is shown with `@Audited Credentials credentials`, `credentials` is a base-list entry, and layer 1 overrides everything — so that exact field is one `[REDACTED]` row and the non-sensitive `user` inside it disappears too. Found by a failing test written from the RFC's example, pinned by `layerOneBlocksAWholeCompositeRatherThanWalkingIntoIt`, and it is the *correct* over-redaction: blocking the subtree beats publishing the leaves of something the list already named untouchable. **Two loud refusals are additions this item makes rather than the RFC:** a marker on a field no accessor exposes (`@Audited private String userName` beside a `getUser()` is attached to nothing, so the component is missing from every record and the omission surfaces during an audit), and two accessors mapping to one component (`getActive()` beside `isActive()`, where picking one silently decides whether a value is published). **The sink follows item 3.2's SPI precedent with the opposite failure policy** — a failing metrics recorder is swallowed, a failing audit sink is wrapped in `AuditWriteException` and thrown, because a missing timing is a lost number and a missing audit record is a compliance hole found at the next review; the catch is the same narrow `RuntimeException | LinkageError`, so an `OutOfMemoryError` still propagates. `LoggingAuditSink` logs at **`INFO`** where the timing fallback logs at `DEBUG`, and says in its own Javadoc that an application log is a fallback and not a compliance store. **A control the register said was unenforceable turned out to be enforced, and only running proved it:** C-03's row read *"no gate forbids the default-locale overload; an ErrorProne pattern would be the way to close that"* — reintroducing `name.toLowerCase()` in `AuditPolicy` produces ErrorProne's **`StringCaseLocaleUsage`**, which `failOnWarning` turns into a build failure. C-03 moves to ✅ with the gate's scope stated (that overload pair, on the JDK 21+ cells ADR-0009 binds ErrorProne to), and **C-05** is created for FR-16 itself. The threat model's two `AuditLog` rows move from ▢/⚠ to ✅; **no boundary row is added**, because RFC-0002 routed "library → host-supplied audit store" to item 8.6, whose owner is the security-auditor. **Visitor is the first entry in the patterns catalogue's Rejected table** — classic Visitor needs every audited type to implement `accept`, which a library cannot ask of a consumer's domain objects, so the reflective walk reaches the same intent without the contract. **No benchmark and no plan cache, both deliberate:** no NFR names FR-16, so a `ClassValue` cache would be either an unbacked performance claim or an invented budget (item 2.4's precedent), and it stays purely additive if a host ever measures a need. **Collections are refused and that is a contract gap rather than a bug** — the four layers are defined over components and have no vocabulary for element-level policy, while `String.valueOf` on a `List<Credentials>` is the composite trap in bulk; the workaround is a rendered `String` component and the way in is an RFC-0002 amendment. The plain-class half of the same warning *is* fixable and was fixed — `AuditEvent`'s five serialisable fields now carry `@serial` — which is what isolates the residue to the record-component case.
