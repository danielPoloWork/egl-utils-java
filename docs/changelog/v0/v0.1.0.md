# v0.1.0 — 2026-07-29

Milestone 1, *Project bootstrap & CI*: the build system, the quality gates and the record system.
**No library API ships in this release** — `d4np-core` and its eight siblings are published as empty,
JPMS-described artifacts. What is delivered is the machinery every later milestone lands into, with
each gate proven to fail on a real violation rather than asserted to work.

## Added

- **The nine-module Maven reactor of ADR-001** — `core`, `jdbc`, `concurrent`, `security`, `json`,
  `spring-adapter`, `lock-redisson`, `test` and the consumer-facing `bom`, on a JDK 17 bytecode
  baseline (`release 17`) exercised on JDK 21.
- **JPMS descriptors for the eight code modules**, with `d4np-core` owning the family root
  `it.d4np.utils` ([ADR-0005](../../adr/0005-jpms-module-names-and-export-less-descriptors.md)). No
  module exports anything yet: `exports` of an empty package is a compile error, so the clauses arrive
  with the types.
- **A six-cell CI matrix** — Linux / Windows / macOS on Temurin 17 **and** 21 — plus a two-platform
  format-and-lint job ([ADR-0004](../../adr/0004-declare-line-endings-and-cross-platform-format-checks.md)).
- **The ADR-001 dependency policy as a build gate** (NFR-08): `maven-enforcer` bound to `validate`,
  per-module and default-deny where the contract is "nothing"
  ([ADR-0006](../../adr/0006-enforce-the-dependency-policy-per-module.md)).
- **JMH and jcstress harnesses** as profile-activated, test-scope source roots, so NFR measurement has
  somewhere to land without adding a dependency to any published artifact
  ([ADR-0007](../../adr/0007-nfr-harnesses-as-test-scope-profiles.md)).
- **ErrorProne 2.50.0 + NullAway 0.13.8** bound to compilation on JDK 21+ toolchains, NullAway at
  `ERROR`, and javac **warnings as errors on every platform**
  ([ADR-0009](../../adr/0009-errorprone-nullaway-on-jdk-21-cells.md)).
- **Spotless (google-java-format) and Checkstyle** at the reactor root, with declared line endings so a
  formatting verdict cannot depend on the contributor's platform.
- **JUnit 5 + AssertJ** with a build-contract smoke test that asserts the toolchain (package root,
  class-file major 61, runtime floor) rather than asserting that tests can run.
- **Six congruence gates in `tools/consistency_lint.py`** beyond the generated ones — `jpms-congruence`,
  `module-dependency-policy`, `harness-opt-in`, `static-analysis-wired`, `spec-authority`, and ADR-index
  status congruence across both id schemes. Each was verified against deliberate breakages.
- **A complete decision record**: fourteen ADRs, indexed in one place, spanning both the governed
  four-digit series and the four binding pre-governance decisions
  ([ADR-0008](../../adr/0008-index-the-pre-governance-adrs-in-place.md)).
- **One specification authority** with a written precedence ladder — RFC over spec, manifest as source
  of record, rendered spec as the published view, intake draft superseded
  ([ADR-0010](../../adr/0010-single-specification-authority.md)).

## Changed

- The CI `benchmark` and `jcstress` jobs stop reporting success without measuring: they invoked Maven
  profiles that did not exist, and Maven only *warns* on an unmatched profile.
- The `compatibility` job invokes `mvn validate` rather than `enforcer:enforce`, which had silently
  skipped every per-module rule while reporting that all rules passed.
- `ROADMAP.md`'s traceability rule now names the manifest as the FR/NFR id source; it previously named a
  document that contains none of those ids.

## Fixed

- `.mvn/jvm.config` carried explanatory `#` lines in a format with no comment syntax, which made *every*
  Maven invocation fail on every platform, including `mvn -v`.
- Three `.gitignore` patterns (`target/`, `*.class`, `*.iml`) were silently disabled by trailing
  comments, leaving nine build directories one `git add -A` from being committed.
- `checkstyle.xml` named a module that does not exist (`IllegalThrow` for `IllegalThrows`), which makes
  Checkstyle reject the entire configuration rather than skip the rule.
- `version-lockstep` compared the README badge against itself, because the generated version path could
  never exist.

## Security

- `maven-enforcer` bans the `javax.*` EE artifacts spec §1.1 puts out of scope, transitively, so a
  banned coordinate cannot enter through a dependency nobody read.
- The `security` (OWASP Dependency-Check) and `compatibility` (japicmp) CI jobs are **still red** — both
  tools are unconfigured, and Milestone 8 items 8.1 and 8.4 own them. Stated because a red gate that is
  known and owned is different from one that is ignored.
