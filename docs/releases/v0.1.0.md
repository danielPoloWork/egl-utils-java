# v0.1.0 — the build system, the gates, and the record

**Released:** 2026-07-29 · **Milestone:** M1 — Project bootstrap & CI · **Baseline:** JDK 17
(`release 17`), exercised on 21 · **Full entries:**
[`docs/changelog/v0/v0.1.0.md`](../changelog/v0/v0.1.0.md)

## What this release is — and what it is not

This is the **foundation release**. It ships the nine-module reactor of ADR-001, its JPMS descriptors,
the six-cell CI matrix, and every quality gate the specification promises — but **no library API**.
`d4np-core` and its siblings are published as empty, module-described artifacts. `Result<T>`, `Lazy<T>`,
`StrategyRegistry` and the rest are Milestone 2 (RFC-0001 has already pinned their contracts).

Nothing here is a consumer-visible API surface, so there is nothing yet for japicmp to guard and no
migration to perform. **0.x means binary compatibility is not yet promised**; that promise starts at
1.0.0, which Milestone 8 delivers once japicmp is actually gating.

## Why it is worth cutting anyway

Because the gates are real, and each one was made to fail before being trusted:

| Gate | Proven by |
|---|---|
| Dependency policy (NFR-08) | a 28-case matrix injecting one banned/allowed dependency at a time |
| JPMS graph | five deliberate breakages, plus `--describe-module` on all eight built JARs |
| jcstress | forbidding an outcome the run does produce → `BUILD FAILURE` |
| ErrorProne + NullAway | a null-pass and a self-assignment probe → both named, build fails |
| Harness wiring | four breakages of the sources ⟺ opt-in bijection |
| Specification authority | five breakages, including a dangling requirement id |
| ADR record | six breakages across both id schemes, plus status congruence |

Four defect classes were found by *running* the toolchain rather than reading it, and are recorded
rather than quietly fixed: config formats with no comment syntax (`.mvn/jvm.config`, `.gitignore`),
gates that pass while measuring nothing (unmatched Maven profiles, `enforcer:enforce` skipping every
per-module rule, an unpinned surefire that runs no tests), platform-dependent verdicts (Spotless line
endings), and tool-version incompatibilities that only a real run surfaces (ErrorProne/NullAway pairing).

## Consuming it

Nothing to consume yet — the artifacts carry no types. When Milestone 2 lands, the BOM is the single
import:

```xml
<dependencyManagement>
  <dependencies>
    <dependency>
      <groupId>it.d4np</groupId>
      <artifactId>d4np-bom</artifactId>
      <version>0.1.0</version>
      <type>pom</type>
      <scope>import</scope>
    </dependency>
  </dependencies>
</dependencyManagement>
```

## Known gaps in this release

- **Two CI jobs are red and owned**: `security` (OWASP Dependency-Check) and `compatibility` (japicmp) —
  neither tool is declared, so both fail with `No plugin found for prefix`. Item **6.4** owns the first
  (it must *introduce* the plugin before tightening it into a CVSS gate, and RFC-0005 in item **6.0**
  settles the threshold and suppression policy the NFR-11 gap leaves open); item **8.1** owns the second.
- **Static analysis does not run on the JDK-17 cells.** ErrorProne 2.43.0+ cannot load on JDK 17; the
  three JDK-21 cells and the `quality` job analyse the same sources, so nothing ships unanalyzed
  ([ADR-0009](../adr/0009-errorprone-nullaway-on-jdk-21-cells.md)).
- **Coverage and mutation gates are not wired** (`-Pcoverage`, `-Pmutation` do not exist) — item **8.2**.
  The 85% line / 60% mutation targets are stated, not enforced.
- **Two ADR id shapes coexist**: `ADR-001` (four pre-governance decisions, still binding) and
  `ADR-0001`… (this docs system). Deliberate, indexed and gated
  ([ADR-0008](../adr/0008-index-the-pre-governance-adrs-in-place.md)).
- **Benchmark numbers are informational.** The only recorded measurement is a harness baseline on a
  developer machine; publication-grade numbers need the reference machine (spec §6).
- **Four requirement `[GAP]` markers remain** — FR-06 transaction semantics, FR-12 AAD, NFR-11 CVSS
  threshold, NFR-12 provenance — each owned by a later RFC.
